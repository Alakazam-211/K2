k2 agent whois — which agent owns a process (owner only)

USAGE
  k2 agent whois <pid> [--json]

WHAT IT SAYS
  The process's cgroup and the agent it is labelled with: every terminal,
  job run and published service of an agent starts in the agent's own
  cgroup (agents/a-<workspace id>/ under the daemon's unit). Also visible
  with systemd-cgls and ps -o pid,cgroup,cmd.

  A label is not proof: an agent without the folder fence runs as you, so
  it can move a process out of its label or into another agent's cgroup,
  or read the owner token on disk. A fenced agent (k2 agent isolation <ws>
  fence) can't write to its cgroup files, but unless the Unix-socket block
  enforces (it records by default), it can still reach systemd's buses and
  your tmux, which can move it.

WHO MAY
  The server's owner, from a terminal outside K2 (an agent's passport is
  refused). Linux only; elsewhere it says identity is unavailable.
