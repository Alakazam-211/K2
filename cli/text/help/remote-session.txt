k2 remote-session — owner/admin Remote Session surface (Layer 0 + grants + shell)

Master switch defaults OFF. Drive (shell/write/read) is denied until enable.
Grants mint a one-time k2rs_… token; shell PTYs and terminal I/O require a
live grant (or owner break-glass on write/read).

USAGE
  k2 remote-session status [--json] [--host HOST] [TOKEN]
  k2 remote-session enable  [--host HOST] [TOKEN]
  k2 remote-session disable [--host HOST] [TOKEN]
  k2 remote-session grant [--scope shell] [--ttl 30m|1800] [--label "..."]
                          [--host HOST] [TOKEN]
  k2 remote-session grants [--json] [--host HOST] [TOKEN]
  k2 remote-session revoke <grant-id> [--host HOST] [TOKEN]
  k2 remote-session shell [--cwd PATH] [--host HOST] [TOKEN]
  k2 remote-session write <session-id> ("text" | - | --text-file PATH) [--keep-newline]
                          [TOKEN] [--host HOST]
  k2 remote-session read  <session-id> [--lines N] [TOKEN] [--host HOST]

  TOKEN is one of --token-file PATH, --token-stdin or --token TOK: an
  owner/admin token for the admin verbs, a k2rs_… grant for the drive verbs.

ADMIN (owner/admin token)
  status     Layer 0 enabled?, active grants/sessions, recent denials
  enable     Turn Remote Sessions ON
  disable    Turn OFF and kill grant-bound shells
  grant      Mint shell grant; prints token ONCE
  grants     List grants (no secrets)
  revoke     Revoke by id (kills bound shells)

DRIVE (prefer a k2rs_… grant token, with --token-file or --token-stdin)
  shell      Spawn daemon-user login shell PTY under the grant
  write      Inject text into a remote-session PTY (terminal/write)
  read       Peek last N lines of a remote-session PTY (terminal/read)

OPTIONS
  --scope shell     Only scope implemented (default shell)
  --ttl <dur>       Grant lifetime: 30m, 45m, 1h, 90s, or bare seconds (1800)
  --label "..."     Optional human label on the grant
  --cwd PATH        Working directory for shell spawn (default: daemon HOME)
  --lines N         Lines for read (default 50)
  --host HOST       Remote daemon (https://HOST or full URL). Reuses
                    connect-tokens / --token-stdin / $K2_REMOTE_TOKEN like k2 talk.
  --token-file PATH Read the token from PATH (its first line). Refused when
                    the file's group or others can read it: chmod 600 PATH
  --token-stdin     Read the token from stdin: owner/connect token (admin)
                    or k2rs_… grant (drive)
  --token TOK       The token on the command line, where other users on
                    this machine can see it; prefer --token-file or
                    --token-stdin
  -                 write: type stdin (on a terminal: one line, not shown
                    as it is typed)
  --text-file PATH  write: type PATH's bytes
  --keep-newline    write: with - or --text-file, keep a trailing newline
                    (by default one is taken off: a final \n, or \r\n)
  --json            Machine-readable status / grants

SECRETS
  A token or text on the command line is visible to every user on this
  machine (ps). Give a secret (a k2rs_… token, a sudo password) with
  --token-file, --token-stdin, write's - or write's --text-file: never as
  a word on the command line or in an environment variable. The text
  word ("text") is for text that isn't secret. write types the bytes of
  - and --text-file as they are, less one trailing newline (\n, or \r\n),
  then Enter, as for the text word: a password file made with echo
  doesn't press Enter twice. --keep-newline sends every byte. They go in
  the request's body, never in its URL.

EXAMPLES
  k2 remote-session enable
  k2 remote-session grant --ttl 30m --label "lab overnight"
  k2 remote-session shell --token-stdin          # paste the k2rs_… token
  k2 remote-session write <session-id> "ls -la" --token-stdin
  k2 remote-session write <session-id> --text-file ./pw --token-file ./grant
  k2 remote-session write <session-id> - --token-file ./grant < ./pw
  k2 remote-session read  <session-id> --lines 80 --token-stdin
  k2 remote-session revoke rs_…
  k2 remote-session status --host box.k2.dev   # owner token from connect-tokens

EXIT CODES
  0  ok
  1  unexpected / transport
  2  usage / bad request
  3  teaching auth: REMOTE_SESSIONS_DISABLED, NO_GRANT, GRANT_*, owner_only
