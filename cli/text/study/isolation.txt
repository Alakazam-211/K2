Agent isolation (Linux servers)

IDENTITY (on wherever the server can have it)
  Every terminal session of an agent runs in that agent's own cgroup,
  agents/a-<workspace id>/ inside the daemon's unit. K5 does this with the
  standard Linux kernel; no custom kernel. It gives two things:
  - Traceable: every process an agent starts is in its cgroup
    (systemd-cgls, ps -o pid,cgroup,cmd, k2 agent whois <pid>).
  - A copied passport alone no longer works: the daemon accepts a session's
    passport only on that session's socket and only from a process in that
    agent's cgroup (else 403 passport_wrong_cgroup, with an audit row), and
    never over loopback TCP (403 passport_needs_socket). `k2` in an agent's
    terminal sends its passport over the session socket by itself.

  What it doesn't do, for an agent without the fence: that agent runs as
  the server's user, so it can move a process into another agent's cgroup,
  and it can read the owner token on disk and call as the owner.

  Where it's unavailable (macOS, a user-unit install, a box prepared before
  0.46.16, a container) passports work as before; /boot-status
  (agentIsolation) and k2 app doctor (agentIdentity) say so and why.
  Emergency off-switch for a broken box: K2_AGENT_CGROUP_IDENTITY=0 in the
  daemon's environment (logged at boot, shown in the doctor).

THE FOLDER FENCE (per agent, off by default, the owner's switch)
  k2 agent isolation <workspace> fence. The agent's next terminals open
  only their workspace, their own temp folder, their own harness login and
  the build caches, and read the system and the toolchains (Landlock). Not
  a sibling's folder, not ~/.k2 (owner token, vault), not ~/.ssh; no sudo;
  no way out of their cgroup. A terminal that can't be fenced doesn't
  start (it says why); never silently unfenced. An agent can't turn its own
  fence off.

  Inside a fence, something refused reads "Permission denied". Builds in the
  workspace, git in the workspace, and the shared caches (cargo, npm, bun,
  pip, uv) work. Installing software (brew, apt, cargo install, npm -g) and
  ssh with your keys don't: ask your person.
