k2 study agent-templates — Agent templates: hire a type of agent, save your own

WHAT A TEMPLATE IS
  A folder of plain files: template.toml (id, version, what the agent
  gets), ROLE.md (the charter), and optional wiki/, context/ and skills/.
  K2 has ten built-in types: general, lead, developer, app-owner, designer,
  researcher, reviewer, writer, support, ops. Templates saved on this server
  (the library, ~/.k2/agent-templates/<id>/v<N>/) list under "Yours".
  Two system templates, kessel and chief-of-staff, are hidden from list
  (--all shows them) and are hired by id only. Old ids still work:
  worker = general, manager = lead, qa = reviewer.
  A template carries no authority: it only suggests permissions.
  The handle is the name in lowercase with dashes ("Rita Lee" → rita-lee).

1. LOOK
  k2 agent template list                  the types
  k2 agent template show writer           its charter, params, questions,
                                          starter notes, layers, suggestions
                                          and the hello it sends
  k2 agent template show writer --files   every file in full
  list --json carries canSave: this server supports saving templates (not
  whether you may).

2. REVIEW, THEN HIRE
  Step 1, review (writes and starts nothing, even with --launch):
  k2 agent hire --template writer --name "Max" --agent codex --dry-run
    Prints the folder (<hire root>/<handle>, here <hire root>/max;
    k2 agent hire-root) and each file, layer and permission with its
    label: would write · skip · yours, kept; a permission says would
    grant · card · refused · skip · declined (part 3). Read it first.
  Step 2, hire and start it:
  k2 agent hire --template writer --name "Max" --agent codex --launch
    Writes the folder, ROLE.md, starter notes, context layers and
    .k2/agent/template.lock, then K2 starts the agent and it says hello
    to its person on the Thread (the Thread is the person's chat with
    the agent).
  Or, to make it without starting it, leave out --launch: nothing starts.
  Start it later with k2 workspace launch <folder>, or open it in the app.
  The hello goes once, the first time the agent starts (any of these
  ways, or a re-run with --launch). Later starts send nothing.
  --name <name>      optional; the display name. Left out, it is the
                     folder's name: the template id with no <dir>
                     (<hire root>/writer), else the <dir> folder's name.
  --agent <preset>   the tool it runs: an id, label (in full, any case)
                     or command word from k2 preset list (codex,
                     claude, ...). One this server doesn't have is usage
                     (exit 2), with the server's presets. Left out: the
                     template's suggested tool if it names one (K2's
                     built-ins don't), else this server's default tool,
                     else Claude.
  --param key=value  a value the template asks for; every built-in takes
                     about="what to focus on" (show lists them).
  --answer id=text   answer a first-conversation question (show lists the
                     ids). Answer only what you know; the agent asks its
                     person the rest on its first start.
  --decline <perm>   leave a suggested permission off (its plan line id).
  <dir>              optional: a folder instead of <hire root>/<handle>.
  Re-running the same hire is safe: the same --template and --name with
  no <dir> reuse <hire root>/<handle>; it writes only what is missing and
  never replaces a file the agent changed. Without --agent it keeps the
  tool set at create. folder_exists means that
  folder holds something else (another agent or other files). One
  template per agent. The hire prints the folder; tell your person who
  you hired and why.
  From an agent's session a hire only makes a new folder inside the hire
  root: an existing one is owner_only (a re-run too), one elsewhere is
  outside_hire_root. A person hires anywhere.

3. PERMISSIONS: THE HIRER'S REACH DECIDES
  A template only suggests switches; a hire never gets more than the
  hirer may give (k2 agent hire --help, PERMISSIONS). Each line says:
    would grant  the hirer may give it: the owner any, an admin what an
                 admin can, an agent only what it has on itself.
    card         an owner or admin is asked on a card on its Thread.
    refused      no card can ask for it: the next line says who can turn
                 it on and how. The hire goes ahead; tell your person.
    skip / declined   already on / left off with --decline <perm> (kept
                      off on a re-run too).

4. SAVE YOUR OWN SETUP AS A TEMPLATE
  k2 agent template save . --id my-writer --summary "Writes our posts" --dry-run
  k2 agent template save . --id my-writer --wiki "Voice and style"
  <ws> is a folder or handle; "." is the workspace you are in, from any
  subfolder (in a K2 terminal, your own; elsewhere, the nearest folder
  with a .k2 above where you stand). Who: people need Owner or Admin (a
  Member gets role_required, but can still use terminal sessions, which
  run as this server's user). An agent may save its own workspace only
  (another one is own_workspace_only); role_required never applies to it.
  Taken: the ROLE.md charter with its "Your notes" part (no
  frontmatter), stacked catalog ids, your own context layers, skills you
  made (not K2's), heartbeats (name, schedule, WAKEUP text), the tool, and
  the permission switches now on, as suggestions. Wiki notes only with
  --wiki <note>: the note's name as k2 wiki list shows it, not a path
  (.md optional).
  Never taken: Threads, transcripts, vault secrets, mail accounts,
  sign-ins, .env files, App logins, connections, or any other file.
  Secrets: a token, API key or private key in a taken file stops the save
  with secret_found, naming the file and line, in a --dry-run too; the
  secret is never printed. Keep it in the vault (k2 study vault) and save
  again. No override: for a false alarm, such as an example key in a
  note, reword or remove it.
  Versions: the first save of an id is v1; you saving it again writes v2,
  v3, ... and keeps the older ones. A hire uses the newest.

5. ADD AND REMOVE
  k2 agent template add ./my-template --dry-run    check a folder only
  k2 agent template add ./my-template              install it
    The folder needs template.toml and ROLE.md. Same checks as save; it
    lands as its id's next version, with you as the author.
  k2 agent template remove my-writer --version 1   one version
  k2 agent template remove my-writer               every version
    Agents already hired from it keep their files. K2's built-ins can't
    be removed; an agent removes only templates it saved.

6. UPGRADE AND DIFF
  k2 agent template diff .                what an upgrade would change
  k2 agent template upgrade . --dry-run   the same report; writes nothing
  k2 agent template upgrade .
  k2 agent template diff my-writer 1 2    two saved versions, file by file
  Per file, by the checksum in .k2/agent/template.lock:
    unchanged since the hire → replaced;
    changed by the agent → kept, and the new text lands beside it as
      <file>.proposed: read it and merge what you want;
    deleted by the agent → stays deleted.
  In ROLE.md only the K2:MANAGED block is replaced, never "Your notes".
  New notes, layers, skills and catalog items are added; new heartbeats
  and suggestions are only listed. Never changed: permissions, tool,
  model, name, connections. The agent gets one inbox note.
  Answers given at hire (--answer, --param) are kept in the lock and
  written into each new version.
  K2's built-ins upgrade by themselves when K2 starts after an update,
  with these same rules; on an agent made from a built-in, diff shows that
  pending upgrade first. A saved template upgrades only when someone runs
  upgrade.

EXIT CODES (the same for k2 agent hire and k2 agent template)
  0  ok
  1  refused for what it is: id_reserved, id_taken, secret_found,
     too_large; or the daemon failed
  2  bad usage: a wrong flag, param, answer or id (usage, bad_id,
     bad_template, no_charter)
  3  not allowed here: template_conflict, folder_exists, system_template,
     own_workspace_only, not_author, role_required, owner_only, hire_off,
     main_only, outside_hire_root
  4  not found: unknown_template, no_template, no_workspace, no_note,
     no_folder, not_found

ERRORS (code (exit): what to do)
  unknown_template (4)    no such id: k2 agent template list --all
  usage (2)               a param or answer the template doesn't take, or
                          an --agent preset this server doesn't have; the
                          message lists the valid ones
  template_conflict (3)   that folder was made from another template; one
                          per agent: pick another folder or --name
  folder_exists (3)       <hire root>/<handle> is taken: another --name,
                          or pass that folder as <dir>
  system_template (3)     an API key can't hire kessel or chief-of-staff;
                          people and agents may, by id
  owner_only (3)          a step only this server's owner takes (such as
                          --db-access read or write for yourself), or an
                          agent hiring into a folder that already exists
  outside_hire_root (3)   an agent hiring outside the hire root
                          (k2 agent hire-root); a person hires anywhere
  bad_id (2)              ids are a-z, 0-9 and -, at most 40 characters
  id_reserved (1)         a K2 id or old id: pick another id
  id_taken (1)            another author saved that id: pick another id
  secret_found (1)        remove the secret from the file and line named
  too_large (1)           a file over 64 KiB, or over 40 notes, 20 skills,
                          20 layers or 12 heartbeats: cut it down
  no_charter (2)          the agent's ROLE.md is missing or empty
  no_note (4)             no such wiki note for --wiki: k2 wiki list
  bad_template (2)        add: the folder fails a check (paths, fields,
                          placeholders); the message says which
  own_workspace_only (3)  an agent works on its own workspace; ask a person
  not_author (3)          an agent removes only what it saved; ask a person
  role_required (3)       a Member person: saving needs Owner or Admin
  no_workspace (4)        no such folder or handle registered on this server
  no_folder (4)           add: that path is not a folder
  not_found (4)           hire: an unknown --connect peer
  no_template (4)         upgrade/diff: that agent wasn't made from one
