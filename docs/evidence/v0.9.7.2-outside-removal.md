# v0.9.7.2 evidence: when an outside save removes someone's text

Every count cites the run that printed it (`[run JOB/RUN:field]`: the run records in
`docs/evidence/runs/`, checked by `tools/evidence/check.py`). The rule, the delivery and the
bounds are in `docs/SESSIONS.md`, "When an outside save removes someone's text"; the event in
`client/WIRE.md`, "The `overwritten` event".

**What v0.9.7.2 adds.** A writer holding older text saves it plus its own change; the kit reads
that as the file deleting what others wrote since. The merge is unchanged: the save is taken in.
What changes is that the person who wrote that text **through the kit** is told what may have
gone, and the note carries their own text so they can paste it back. Before, the line left the
live doc with `Ingested`, no conflict, and nothing said to anyone (the probe on
`probe/stale-buffer-main`, `tests/stale_buffer.rs`).

Kit commits on `notes/removed-text`, from v0.9.7.1 (`500d7fb`): `76c4694` (the notes),
`f9a5016` (docs, wire, soak counts, version), `e20557c` (a soak borrow), `e685d6f` (the soak
counts every delivery), `e40aba5` (the host's edit calls leave waiting notes; the capabilities
golden), `491fac4` (rustfmt), `52416fe` (two test-only soak settings from main).

## 1. The exact strings

Pinned by `crates/base/tests/outside_removal_notes.rs` (each line is asserted whole there):

```text
An outside save may have removed your text (L2). Version 41 holds it. Copy it back from there: restoring that version replaces the outside save's change and everything since. It read "the agent's line\n".
An outside save may have replaced your text (L2). Version 41 holds it. Copy it back from there: restoring that version replaces the outside save's change and everything since. It read "alpha beta\n"; the file now has "alpha gamma".
An outside save may have removed your text (L2). It read "sam's line\n".
... N more characters not shown; version 41 has them.
... N more characters not shown; someone with history access can restore it from version 41.
An outside save may have removed your text (L2). The text is no longer held here. Version 41 holds it. Copy it back from there: restoring that version replaces the outside save's change and everything since.
An outside save may have removed your text (L3). The text is no longer held here. Someone with history access can restore it from version 41.
An outside save may have removed your text (L2). The text is no longer held here. See change 8 in the log.
An outside save may have removed or replaced your text in 7 more places. See change 90 in the log. Version 41 holds the latest of it.
```

On stderr each is one line after `note: `. The text inside is escaped (`\n`, `\"`, `\\`), and
`text_with_quotes_and_backslashes_comes_back_exactly` recovers it exactly. "May have" is in
every sentence because the kit can't tell a removal from a move
(`a_moved_line_is_reported_with_may_have`). A reader without the history right is never told to
open a version (`a_cut_note_says_so_and_what_it_carries_pastes_back` checks `show` refuses
them, and the line doesn't say "Copy it back from there").

## 2. The way back, end to end

`the_author_pastes_the_notes_text_back_and_keeps_the_savers_change`: an agent takes the text
out of its stderr line alone, a person out of the pushed event alone; each writes it back with
an ordinary edit and ends with their text and the saver's. Also `a_cut_note_…` (what a cut note
carries pastes back), `an_agent_returning_after_unload_gets_its_text_and_pastes_it_back` (the
session unloaded in between), and `restoring_the_version_replaces_the_savers_change` (what the
note says about `restore` is true).

## 5. The cost under the session's lock

`removal_cost_on_a_whole_document_delete` (ignored; release), node job `054691c2` (`e20557c`,
a shared build node): an outside save that deletes the whole doc. `removal_us` is the time spent working
out whose text it removes, under the lock; the save's whole time for comparison.

| Lines | Changes that wrote them | Removal (µs) | Whole save (µs) |
|---|---|---|---|
| 10,000 [run 054691c2/removal_cost_10000_4:lines] | 4 | 1,620 [run 054691c2/removal_cost_10000_4:removal_us] | 24,647 [run 054691c2/removal_cost_10000_4:save_us] |
| 100,000 [run 054691c2/removal_cost_100000_4:lines] | 4 | 17,341 [run 054691c2/removal_cost_100000_4:removal_us] | 421,170 [run 054691c2/removal_cost_100000_4:save_us] |
| 5,000 [run 054691c2/removal_cost_5000_5000:lines] | 5,000 [run 054691c2/removal_cost_5000_5000:edits] | 15,214 [run 054691c2/removal_cost_5000_5000:removal_us] | 32,388 [run 054691c2/removal_cost_5000_5000:save_us] |
| 20,000 [run 054691c2/removal_cost_20000_20000:lines] | 20,000 [run 054691c2/removal_cost_20000_20000:edits] | 66,235 [run 054691c2/removal_cost_20000_20000:removal_us] | 161,825 [run 054691c2/removal_cost_20000_20000:save_us] |

It grows with the number of changes whose text the save removes (a store lookup per run of one
change), not with the lines alone: 4 % of the save at 100,000 lines from 4 changes, 41 % at 20,000
lines from 20,000 changes. A shared node: these are rough. The worst case measured, 66 ms under
the lock, is a save that deletes 20,000 separately written lines at once.

## 7. Known limits (in the CHANGELOG)

- **File-tool text has no author to tell.** Text that came in through a file save is
  `kit:external`, so two agents overwriting each other through their own file tools get no note,
  only an audit row (`kit_external_text_gets_no_note`; the soak's rows for `kit:` authors are
  this, 1,093 [run dcb901b9/soak_32_notes:rows_kit] in the 600 s run).
- Text past 32 places in one note isn't carried (counted in `not_shown`, and said).
- Roll-ups carry no text: past 64 waiting notes per person per doc, the rest are a count.
- Typing in flight at the start of a removed line lands on the next line with no signal.
- Notes are lost on a daemon restart; the version, the log and the audit row remain.

**Not decided here:** a saver hook (a host naming who made an outside save) stays out of this
release; restart persistence is for a later release with a store table.
