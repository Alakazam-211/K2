k2 study app-push — notifications to a custom App's own phone app

THE MODEL
  Your App's own phone app (your bundle id, Apple team, Firebase project)
  gets notifications from K2. The owner gives K2 the App's Apple key and/or
  Firebase service account once; K2 keeps them in the vault and the daemon
  sends to Apple and Google itself (no K2 Connect relay). The App, its agent
  and other Apps use the keys, never read them. Push is per App and off
  until the owner approves push:send (or runs k2 app push on).

ONCE, AS THE OWNER (from a terminal outside K2; Touch ID confirms)
  Apple: Push Notifications on for the app id; an APNs key (.p8), its Key ID,
  your Team ID. Firebase: Project settings > Service accounts > Generate new
  private key (google-services.json / GoogleService-Info.plist: in the app).
  k2 app push setup <app> --apns-key AuthKey_XXXX.p8 --key-id XXXX \
      --team-id YYYY --bundle-id com.you.app --fcm-service-account sa.json
  k2 app push check <app>      a fake token: says whether each key works
  k2 app push on <app>         (confirmed again; or approve push:send in a deploy)

IN THE PHONE APP (the guest's own session pass, Authorization: Bearer)
  1 Sign in with a device: POST /cli/skin/login {username, password, app,
    device: {id, name}}; keep the pass and refresh token in the Keychain /
    Keystore; POST /cli/skin/refresh for the next pair.
  2 Take the NATIVE token after the permission prompt: the APNs device token
    as hex, or the FCM token (Expo: getDevicePushTokenAsync).
  3 Every launch and token change: POST /cli/skin/push/register {deviceId,
    platform: apns|fcm, pushToken, environment: sandbox|production} (debug
    builds are sandbox). Answer: id, who, configured {apns, fcm}; no token.
  4 Sign-out: POST /cli/skin/push/unregister {deviceId} before the next sign-in
    (else token_in_use). push.device / push.prefs: previews, mutedTopics.
  5 Receive: your data keys plus k2App, k2Send, k2Kind (app, agent or chat),
    k2Topic and k2Who (match register's who to tell accounts apart).
  6 Sensitive content: send a short line and an id; fetch the rest on open.

VIA THE APP'S SERVER (phone → your server → K2, with the person's own pass)
  await k2.asGuest(pass).push.register({deviceId, platform, pushToken})
  While a Thread or chat is open, every 30 s: push.viewing({conversation,
  visible: true}) (a thread.* id or "chat:<k2Conv>") quiets it for 90 s;
  visible: false ends it. Thread socket: {"t":"viewing","visible":true}.
  Tauri has no push plugin: a native one hands you the APNs or FCM token.

FROM THE APP
  On its link (push:send): await k2.push.send({to: {guest}, title, body,
    data, topic}), then k2.push.status({sendId}); k2.push.devices().
  A BFF outside the wall: POST /v1/apps/<id>/push/send with an App key
    (k2 app key mint <app> --scopes push).
  to: {guest} | {guests: [...]} (at most 1,000) | {room} (one of its rooms).
  Only this App's guests; anyone else is skipped.not_a_guest.

CHAT PUSHES (DMs and channels in the App's Sew Space; off by default)
  k2 app push set <app> --chat on (and K2_APP_CHAT_PUSH=1). DMs always push; a
  channel at the person's level. A tap opens YOUR phone app. With previews on,
  the sender's name and the start of each message go through Apple's and
  Google's push services; off, only "New message". docs/app-push-mobile.md

THE APP'S AGENT
  k2 app push status|log <app> (Build and run Apps); send, test, set
  --agent-replies / --chat (…and manage them end to end). Never the keys:
  ask the owner with a permission card.

LIMITS (an hour): 600 push.send calls per App; 30 alerts and 60 silent
  pushes per guest; 20,000 device sends per App; 5,000 waiting
  (push_queue_full); 20 phones per guest, 10,000 per App (--max-devices).

REFUSALS
  push_off  push_not_configured (no key)  push_server_only (the App's server
  registers)  not_for_host  guest_required  token_in_use  channel_unavailable
  (k2-companion isn't ready)  too_many_recipients  outside_app_rooms
  rate_limited (retryAfterMs)  too_large (4,096 bytes)  airgap  vault_closed
  app_pass_required / cap_not_granted (push.send)  skin_room / pass_wrong_link
  (push.viewing, register)  Any id: k2 explain <id>

WHEN APPLE OR GOOGLE SAY NO
  A gone token removes that device. A token "from another app" before the
  key's first accepted send means a wrong bundle id / project: sends pause,
  nothing is deleted. A refused key pauses that platform 10 minutes and
  leaves the App's agent a note (k2 app push status shows the code).
  K2_APP_PUSH=off in the daemon's environment stops every App's push. The
  owner's k2 push log shows each phone added or removed, and why. K2
  Companion's phones are k2 push. QR pairing registers: k2 study app-pairing.
