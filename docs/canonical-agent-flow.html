Why this fixes today's bug: right now CLAUDE.md symlinks down to a buried .k2/skills/k2so/SKILL.md that the persona is stuffed inside — the PRD calls that "a genuine bug." Flipping it so AGENTS.md is the hub means edits have one home (AGENT.md / PROJECT.md) and every tool agrees.

4 · Skills  (separate lane — loaded on demand, NOT in the entrypoint)

.k2/skills/k2-cli/SKILL.md
Always shipped. The full K2 CLI reference (k2 msg, k2 heartbeat, k2 inbox…). Loaded when the agent actually needs to drive the CLI — keeps the entrypoint lean instead of carrying the whole manual every turn.
.k2/skills/k2-canonical-agents/SKILL.md
Always shipped. The operator skill the user loads with an AI assistant to set up / refresh canonical agents: read existing harness files → merge into AGENT.md with judgment → regenerate AGENTS.md → lay the symlinks.
The distinction that makes this work: a skill is knowledge the agent pulls in when relevant. The entrypoint (AGENTS.md) is what's true every session. So persona/project belong in the entrypoint; "how to use the CLI" and "how to run the canonical-agent setup" are capabilities → skills. Two files, always present in .k2/skills/ for a fresh K2 workspace.

5 · Enablement — new vs existing project  (the warning)

New project

No existing harness files to lose. Checking the box (or first regen) generates AGENTS.md and lays the symlinks directly. Safe, instant.

Existing project ⚠

Already has a real CLAUDE.md / AGENTS.md. A blunt symlink would clobber it. Run the k2-canonical-agents skill with an AI so it merges your current content into AGENT.md first, then the symlinks take over.
Checkbox warning copy (draft): "Enabling fan-out symlinks your harness files (CLAUDE.md, AGENTS.md…) onto K2's generated canon and can overwrite existing content. For a project that already has these files, run the Canonical Agent with an AI assistant instead — it merges your current files in safely. The checkbox is best for new projects."

Open decisions to lock before we build

  1. Symlink vs. copy for mirrors. Symlink = one source of truth, zero drift, but a tool that writes to CLAUDE.md writes through to AGENTS.md. Copy+marker-inject preserves per-harness hand edits but can drift. Recommendation: symlink (mirrors are declared read-only; edits go to AGENT.md/PROJECT.md).
  2. Does the checkbox stay, or does the AI skill become the only path? Proposal: keep the checkbox for new projects (instant), gate it behind the warning; the AI skill is the recommended path for existing ones. (Also fix GAP 1 so checking it actually regenerates now, not on next boot.)
  3. k2so → k2 rename rides along. Folder skills/k2so → the new skills/k2-cli + skills/k2-canonical-agents; markers K2SO:* → K2:*; frontmatter k2so_skill → k2_skill; body brand. Do it as part of this redesign, not before (the composition is changing anyway).
  4. Migration. Existing workspaces have .k2/skills/k2so/SKILL.md + a CLAUDE.md symlink pointing into it. Boot migration: generate AGENTS.md from the existing AGENT.md/PROJECT.md, repoint CLAUDE.md → AGENTS.md, drop the two new skills, retire the old composed skill. Idempotent, mirrors the .k2so→.k2 cutover.
