k2 zen — build Zen Gardens on this computer (~/.k2/zen)

Zen Mode is a mode of a K2 desktop window. In Zen the window shows a Garden:
a personal page on this computer. Zen starts with Garden 1, the texting page,
Garden 2, empty, for you to ask your agents to build, and (on a new computer)
the Diary: a haunted journal with one page per agent on this computer.
+ New Garden opens one window: a name and the ready-made Gardens as cards
(the Diary, the Kanban, Start with the default, Start empty and ask my agent).
An empty Garden is filled by agents editing its file,
gardens/<id>.toml (K2's built-in widgets in columns, plus theme tables).
~/.k2/zen holds only your changes on top of K2's read-only themes and
templates: gardens/<id>.toml (one Garden), zen.toml (every Garden) and
themes/<name>/ (your theme bundles). Edit a file, then validate. A file with
errors is not shown: Zen keeps the last good version and shows the error line.

USAGE
  k2 zen garden list [--json]
  k2 zen garden new <name> [--texting] [--at <n>] [--json]
  k2 zen garden rename <garden> <name> [--json]
  k2 zen garden reorder <garden> <position> [--json]
  k2 zen garden template <garden> texting|blank [--force] [--json]
  k2 zen garden delete <garden> [--json]
  k2 zen garden lock | unlock <garden> [--json]
  k2 zen garden put <garden> --from <file>|- [--note "…"] [--json]
  k2 zen theme list [--garden <name|id>] [--json]
  k2 zen theme next | prev [--garden <name|id>] [--json]
  k2 zen theme set <name> [--garden <name|id>] [--json]
  k2 zen theme set --garden <name|id> --clear
  k2 zen theme new <name> [--from <theme>] [--json]
  k2 zen widget new <name> [--from k2:diary|hello|arcade] [--json]
  k2 zen widget list [--json]
  k2 zen widget sign <name> [--json]      # stamp this version as made by you (or this agent)
  k2 zen widget claim <name> [--json]     # It's mine: the person only, outside K2
  k2 zen widget put <name> <file> --from <path>|- [--note "…"] [--json]
  k2 zen widget put [<name>] --dir <folder> [--prune] [--note "…"] [--json]   # the whole folder
  k2 zen widget apply --from <folder> [<name>] [--prune] [--json]            # = put --dir
  k2 zen widget preview --dir <folder> [<name>] [--config k=v]... | --clear [--json]
  k2 zen widget preview --dir <folder> --shot <png> [--theme dark|light] [--width N] [--height N] [--data f.json]   # headless PNG
  k2 zen proposals [--all] [--json]       # Garden/widget changes waiting for approval
  k2 zen proposals show|approve|reject <id> [--json]
  k2 zen validate [--garden <name|id> [--from <file>|-] | --theme <name> | --widget <name> [--sign] [--types[=all]] | --dir <folder> [--as <name>] | --file <file>] [--strict] [--json]
  k2 zen inspect <file.k2garden | folder> [--json]   review a Garden you received (static; never runs it)
  k2 zen widget errors <name> [--since <seq>] [--follow] [--json]
  k2 zen reload [--json]
  k2 zen reset [--garden <name|id> | --theme <name> | --widget <name> | --file <file>] [--to <snapshot>] [--json]
  k2 zen history [--garden <name|id> | --theme <name> | --widget <name> | --file <file>] [--json]
  k2 zen doctor [--json]
  k2 zen path
  k2 zen sync [--json]
  k2 zen sync <garden> on|off|preview [--page|--theme] [--json]
  k2 zen sync <garden> undo [--json]
  k2 zen sync <garden> keep-previous [--page|--theme] [--json]
  k2 zen news [--json]
  k2 zen news seen [<id>... | --all] [--json]
  k2 zen guide [<topic>] [--json]
  k2 zen data <list|show|grant|revoke|admin|unadmin|delete|move|export|import> …
  k2 zen guide example [<name> [--toml] | --list]

COMMANDS
  garden    The Gardens on this computer. list (* = its own theme); new makes
            an empty Garden (--texting: the texting page) and prints its id
            and file; rename and reorder (1-based) keep the id; template
            turns a Garden into the texting page (texting, the default) or an
            empty page (blank), keeping its id, name and place and the old
            file in .history/ (--force when the file has its own layout,
            widgets or theme tables); delete moves the page into .history/
            (the last Garden stays). lock/unlock are for the person only:
            a locked Garden can't be changed by agents (list marks it).
            <garden> is an id or a name.
  theme     The active theme: one for this computer, plus an optional pick
            per Garden (--garden). list shows K2's themes and yours (* =
            active); next/prev cycle them; set picks one; new copies a theme
            into ~/.k2/zen/themes/<name>/ for you to edit. K2's themes are
            basic, paper, midnight, haunted and glass. An unknown name exits 1.
  widget    Custom widgets: your own sealed HTML, CSS and JS in
            ~/.k2/zen/widgets/<name>/. new copies a working example
            (--from k2:diary, hello or arcade) and prints the folder; list
            shows each widget's state, caps and every placement. Widgets can
            talk to your agents right away: no permissions, no review. If a
            widget posts too much (120 in 10 minutes), K2 pauses its posting
            until the person clicks Resume on it. k2 zen guide api lists the
            k2 object's helpers.
  validate  Check what is on disk now. Prints file:line:col: message for
            each error and exits 1; exits 0 when every file is clean (a
            placed widget not yet run in a Zen window is "pending": exit 0,
            or 2 with --strict). Runtime errors fail only for a widget a
            Garden places, on its saved version, from the last 24 h; the
            rest are warnings (k2 zen widget errors <name> --clear drops
            them). With no target it lists each widget, where it is placed
            and its runtime state. --dir checks a staged widget folder
            anywhere on disk and --garden <g> --from <file> a staged page:
            nothing is written. A check never signs; --widget --sign does
            (--no-sign is still accepted and does nothing).
            k2 zen validate --help has the details.
  reload    Re-read now (the daemon also watches the folder) and print errors.
  reset     Keep the current file as a snapshot, then restore --to <snapshot>,
            or clear your changes: zen.toml goes back to empty, a Garden to
            its template's stub, an override of a built-in theme is removed.
            Defaults to zen.toml.
  history   List the last 20 good versions of each file (newest first),
            deleted Gardens included.
  doctor    Check the folder, Garden list, templates, watcher, history,
            the sync state, K2's archived defaults and the frame floor.
  path      Print the Zen folder.
  sync      Whether each Garden's page and theme sync with K2's defaults
            (they follow K2's improvements) or are its own copy (no K2
            update changes them). on/off/undo/keep-previous change it and
            are for the person only (agents get 403: ask the person to use
            Settings → Gardens). preview prints the Garden as if synced
            and writes nothing. Default part: both.
  news      Unseen Garden news: new catalog Gardens and K2 defaults a
            synced Garden picked up. seen marks ids (or --all) as read.
  guide     The user guide: short pages (gardens, files, widgets, bands,
            required, menus, themes, sync, examples, undo, safe-mode, api)
            and whole example files to pipe into a Garden. Needs no daemon.
  put       garden put writes one Garden page (gardens/<id>.toml); widget
            put writes one code file (.html .js .css .json) in a widget
            folder (made if missing), or with --dir a whole staged folder
            (code, images, fonts) in one checked write: a folder with errors
            writes nothing; --prune also removes files the folder doesn't
            have. All go through the daemon: a page with errors is refused
            and nothing is written, a locked Garden is refused (exit 3),
            K2's built-in widgets (k2:<name>) and defaults are never
            written, and the old page is kept in .history/ (k2 zen reset
            --to). Keep your widget outside ~/.k2 and put it from there.
  preview   widget preview --dir places a staged folder, as
            preview-<name>, alone on K2's own "Widget preview" Garden
            (never one of yours), with --config key=value for its placement
            (e.g. sources=fleet). --clear removes it. The person, or an
            agent with the switch. --shot <png> [--theme dark|light]
            [--width N] [--height N] [--data f.json] renders it headless
            instead (stand-in data, WebKit; writes only the PNG; any local
            agent). Needs Node + Playwright WebKit.
  proposals Garden and widget changes waiting for approval. show prints the
            content; approve applies it (only if the file is unchanged since,
            else proposal_stale); reject drops it (an agent may withdraw its
            own).

AGENTS AND "MANAGE GARDENS AND DATA SOURCES"
  A per-agent switch (Settings → Workspaces → <ws> → Agent; owner/admin:
  k2 sources access on|off --workspace <ws>). Inside a K2 terminal put and
  proposals carry your session's passport.
  Off (the default): garden put / widget put become a proposal that a person
  approves (nothing is written until then; put --dir proposes each changed
  code file); you can withdraw your own. preview needs the switch.
  On: put writes right away, garden new makes a Garden, and you may approve
  or reject proposals. Each act is logged with the agent and session
  (Settings → Logs → Access Audit). Only the owner or an admin flips it.
  Either way: never edit a locked Garden, and never write K2's built-ins.

RULES
  New to Gardens? k2 zen guide. Moving controls? k2 zen guide bands, then
  k2 zen guide required.
  "In my Zen Garden ... (id g-...)" means: edit ~/.k2/zen/gardens/<id>.toml.
  Run `k2 zen validate --garden <id>` before you say it's done.
  Never write grants.json, gardens.json, active.json, sync.json, news.json,
  .defaults/, .locks/ or .history/: K2 writes them.
  A locked Garden: don't edit it. Ask the person. K2 puts back edits to
  its file and refuses k2 zen changes to it with exit 3 (garden_locked).
  Editing a Garden's file never changes whether it syncs; only the person
  turns sync on or off (Settings → Gardens). k2 zen guide sync.
  A custom widget: k2 zen validate --widget <name>; it talks to your
  agents as soon as it's placed (no permissions to ask for).
  Load the k2-zen skill for the page grammar, every widget prop and token.

EXIT
  0 ok · 1 errors (validate) or a refused request · 2 a usage error (an
  unknown guide topic or example included) · 3 Zen isn't set up on this
  computer (turn it on with the Zen toggle in the K2 app's top bar), or the
  Garden is locked / only the person may do this: stop and ask · 4 no such
  proposal, Garden or widget.

AGENTS AND "MANAGE GARDENS AND DATA SOURCES"
  A per-agent switch (Settings → Workspaces → <ws> → Agent; owner/admin:
  k2 sources access on|off --workspace <ws>). Inside a K2 terminal put and
  proposals carry your session's passport.
  Off (the default): garden put / widget put become a proposal that a person
  approves (nothing is written until then; put --dir proposes each changed
  code file); you can withdraw your own. preview needs the switch.
  On: put writes right away, garden new makes a Garden, and you may approve
  or reject proposals. Each act is logged with the agent and session
  (Settings → Logs → Access Audit). Only the owner or an admin flips it.
  Either way: never edit a locked Garden, and never write K2's built-ins.

RULES
  New to Gardens? k2 zen guide. Moving controls? k2 zen guide bands, then
  k2 zen guide required.
  "In my Zen Garden ... (id g-...)" means: edit ~/.k2/zen/gardens/<id>.toml.
  Run `k2 zen validate --garden <id>` before you say it's done.
  Never write grants.json, gardens.json, active.json, sync.json, news.json,
  .defaults/, .locks/ or .history/: K2 writes them.
  A locked Garden: don't edit it. Ask the person. K2 puts back edits to
  its file and refuses k2 zen changes to it with exit 3 (garden_locked).
  Editing a Garden's file never changes whether it syncs; only the person
  turns sync on or off (Settings → Gardens). k2 zen guide sync.
  A custom widget: k2 zen validate --widget <name>; it talks to your
  agents as soon as it's placed (no permissions to ask for).
  Load the k2-zen skill for the page grammar, every widget prop and token.

k2 zen — build Zen Gardens on this computer (~/.k2/zen)

Zen Mode is a mode of a K2 desktop window. In Zen the window shows a Garden:
a personal page on this computer. Zen starts with Garden 1, the texting page,
Garden 2, empty, for you to ask your agents to build, and (on a new computer)
the Diary: a haunted journal with one page per agent on this computer.
+ New Garden opens one window: a name and the ready-made Gardens as cards
(the Diary, the Kanban, Start with the default, Start empty and ask my agent).
An empty Garden is filled by agents editing its file,
gardens/<id>.toml (K2's built-in widgets in columns, plus theme tables).
~/.k2/zen holds only your changes on top of K2's read-only themes and
templates: gardens/<id>.toml (one Garden), zen.toml (every Garden) and
themes/<name>/ (your theme bundles). Edit a file, then validate. A file with
errors is not shown: Zen keeps the last good version and shows the error line.

COMMANDS
  garden    The Gardens on this computer. list (* = its own theme); new makes
            an empty Garden (--texting: the texting page) and prints its id
            and file; rename and reorder (1-based) keep the id; template
            turns a Garden into the texting page (texting, the default) or an
            empty page (blank), keeping its id, name and place and the old
            file in .history/ (--force when the file has its own layout,
            widgets or theme tables); delete moves the page into .history/
            (the last Garden stays). lock/unlock are for the person only:
            a locked Garden can't be changed by agents (list marks it).
            <garden> is an id or a name.
  theme     The active theme: one for this computer, plus an optional pick
            per Garden (--garden). list shows K2's themes and yours (* =
            active); next/prev cycle them; set picks one; new copies a theme
            into ~/.k2/zen/themes/<name>/ for you to edit. K2's themes are
            basic, paper, midnight, haunted and glass. An unknown name exits 1.
  widget    Custom widgets: your own sealed HTML, CSS and JS in
            ~/.k2/zen/widgets/<name>/. new copies a working example
            (--from k2:diary, hello or arcade) and prints the folder; list
            shows each widget's state, caps and every placement. Widgets can
            talk to your agents right away: no permissions, no review. If a
            widget posts too much (120 in 10 minutes), K2 pauses its posting
            until the person clicks Resume on it. k2 zen guide api lists the
            k2 object's helpers.
  validate  Check what is on disk now. Prints file:line:col: message for
            each error and exits 1; exits 0 when every file is clean (a
            placed widget not yet run in a Zen window is "pending": exit 0,
            or 2 with --strict). Runtime errors fail only for a widget a
            Garden places, on its saved version, from the last 24 h; the
            rest are warnings (k2 zen widget errors <name> --clear drops
            them). With no target it lists each widget, where it is placed
            and its runtime state. --dir checks a staged widget folder
            anywhere on disk and --garden <g> --from <file> a staged page:
            nothing is written. A check never signs; --widget --sign does
            (--no-sign is still accepted and does nothing).
            k2 zen validate --help has the details.
  reload    Re-read now (the daemon also watches the folder) and print errors.
  reset     Keep the current file as a snapshot, then restore --to <snapshot>,
            or clear your changes: zen.toml goes back to empty, a Garden to
            its template's stub, an override of a built-in theme is removed.
            Defaults to zen.toml.
  history   List the last 20 good versions of each file (newest first),
            deleted Gardens included.
  doctor    Check the folder, Garden list, templates, watcher, history,
            the sync state, K2's archived defaults and the frame floor.
  path      Print the Zen folder.
  sync      Whether each Garden's page and theme sync with K2's defaults
            (they follow K2's improvements) or are its own copy (no K2
            update changes them). on/off/undo/keep-previous change it and
            are for the person only (agents get 403: ask the person to use
            Settings → Gardens). preview prints the Garden as if synced
            and writes nothing. Default part: both.
  news      Unseen Garden news: new catalog Gardens and K2 defaults a
            synced Garden picked up. seen marks ids (or --all) as read.
  guide     The user guide: short pages (gardens, files, widgets, bands,
            required, menus, themes, sync, examples, undo, safe-mode, api)
            and whole example files to pipe into a Garden. Needs no daemon.
  put       garden put writes one Garden page (gardens/<id>.toml); widget
            put writes one code file (.html .js .css .json) in a widget
            folder (made if missing), or with --dir a whole staged folder
            (code, images, fonts) in one checked write: a folder with errors
            writes nothing; --prune also removes files the folder doesn't
            have. All go through the daemon: a page with errors is refused
            and nothing is written, a locked Garden is refused (exit 3),
            K2's built-in widgets (k2:<name>) and defaults are never
            written, and the old page is kept in .history/ (k2 zen reset
            --to). Keep your widget outside ~/.k2 and put it from there.
  preview   widget preview --dir places a staged folder, as
            preview-<name>, alone on K2's own "Widget preview" Garden
            (never one of yours), with --config key=value for its placement
            (e.g. sources=fleet). --clear removes it. The person, or an
            agent with the switch. --shot <png> [--theme dark|light]
            [--width N] [--height N] [--data f.json] renders it headless
            instead (stand-in data, WebKit; writes only the PNG; any local
            agent). Needs Node + Playwright WebKit.
  proposals Garden and widget changes waiting for approval. show prints the
            content; approve applies it (only if the file is unchanged since,
            else proposal_stale); reject drops it (an agent may withdraw its
            own).

AGENTS AND "MANAGE GARDENS AND DATA SOURCES"
  A per-agent switch (Settings → Workspaces → <ws> → Agent; owner/admin:
  k2 sources access on|off --workspace <ws>). Inside a K2 terminal put and
  proposals carry your session's passport.
  Off (the default): garden put / widget put become a proposal that a person
  approves (nothing is written until then; put --dir proposes each changed
  code file); you can withdraw your own. preview needs the switch.
  On: put writes right away, garden new makes a Garden, and you may approve
  or reject proposals. Each act is logged with the agent and session
  (Settings → Logs → Access Audit). Only the owner or an admin flips it.
  Either way: never edit a locked Garden, and never write K2's built-ins.

RULES
  New to Gardens? k2 zen guide. Moving controls? k2 zen guide bands, then
  k2 zen guide required.
  "In my Zen Garden ... (id g-...)" means: edit ~/.k2/zen/gardens/<id>.toml.
  Run `k2 zen validate --garden <id>` before you say it's done.
  Never write grants.json, gardens.json, active.json, sync.json, news.json,
  .defaults/, .locks/ or .history/: K2 writes them.
  A locked Garden: don't edit it. Ask the person. K2 puts back edits to
  its file and refuses k2 zen changes to it with exit 3 (garden_locked).
  Editing a Garden's file never changes whether it syncs; only the person
  turns sync on or off (Settings → Gardens). k2 zen guide sync.
  A custom widget: k2 zen validate --widget <name>; it talks to your
  agents as soon as it's placed (no permissions to ask for).
  Load the k2-zen skill for the page grammar, every widget prop and token.
